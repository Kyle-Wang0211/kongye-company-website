# Clean scene while choosing a spatial comment position

Entering explicit surface-comment selection hides all saved comment pins, halos and preview cards immediately. Host spatial layout becomes null. Marker refreshes and camera updates must not show them until the host exits selection; stale hidden-marker pointer, wheel and click handlers cannot select existing comments. Exiting restores saved markers without deleting comment state or altering camera, model, approval or storage. A picked draft returns as the existing white point once the host accepts the anchor and exits selection.

Apply this presentation-state adaptation in the existing shared GLB/PLY viewer used by community and miniprogram. No new renderer, intersection/projection method, vendor revision, dependency, backend or phone update. Native Three.js 0.186.1 geometry/picking and Sculpt-derived adapter remain unchanged. This is product UI adaptation, not a new academic algorithm or a claim of byte-identical upstream behavior. New streamed formats not using this adapter are outside the demonstrated scope and must preserve the same product behavior when integrated.

Acceptance: baseline's 18 surface-comment tests plus 4 GLB/PLY mode tests; show the new requirements failing on the baseline.
